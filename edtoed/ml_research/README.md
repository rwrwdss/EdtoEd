# Обучение модели

Обновлённый протокол: train 2013, validation 2014B, test 2014J; повторные студенты исключены из поздних выборок. Сдачи после дня 28 и зачтённые ранее работы исключаются. Ушедшие до/на день 28 и ещё не зарегистрированные студенты исключаются. ROC-AUC 0.691, F1 0.573 на 7929 тестовых зачислениях. Это исследовательский кандидат, не продвинутая serving-модель. Старые метрики не являются независимой оценкой. Для promotion нужны parity-тесты и согласованный контракт cohort/window.

Проверки протокола: `python3 -m unittest test_training -v`.

Первый воспроизводимый baseline реализован в `train_oulad.py`. Он обучается на OULAD на уровне зачисления, использует только первые 28 дней курса и экспортирует совместимый с контрактом проекта ONNX с входом `float_input` формы `[N, 3]`.

```bash
cd edtoed/ml_research
python3 train_oulad.py
```

Скрипт создаёт `artifacts/oulad_baseline_report.{json,md}` и исследовательский `artifacts/edtoed_oulad_v1.onnx`. После принятия модели для сервиса её нужно скопировать в `models/edtoed_v1.onnx`; в production-папке `models/` хранится только один актуальный ONNX-файл. Сырые данные скачиваются отдельно и игнорируются Git.

Признаки сохраняют порядок из `internal/features`: `relative_clicks`, `test_score`, `deadline_delay`. Целевая метка baseline: `Fail` или `Withdrawn` = 1, `Pass` или `Distinction` = 0. Разбиение выполняется по `id_student`, а признаки ограничены первыми 28 днями, чтобы не смешивать одного студента между выборками и не использовать итог курса.

Для переобучения на production-логах нужны подтверждённые метки оттока. Поле `is_trained` в таблице отмечает обработку события, но не заменяет целевую метку. OULAD используется только как исследовательский baseline и не является доказательством качества на данных конкретной LMS.
